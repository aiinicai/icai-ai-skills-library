# ICAI CA AI Skills Library

**A structured catalogue of reusable AI Skills for Chartered Accountants in practice, industry, education and allied professional roles.**

The **ICAI CA AI Skills Library** organizes task-focused AI Skills by professional domain so users can discover, evaluate and apply them more easily. Each Skill should describe the task it performs, the input it needs, the output it produces, and the checks that remain the responsibility of a qualified professional.

> **Important:** This README proposes a repository taxonomy and quality framework. Inclusion of a Skill in the catalogue does not, by itself, constitute official ICAI approval, professional certification, or a substitute for applicable laws, standards and independent professional judgment.

## Category details and suggested Skills

The subcategories and Skill names below are **illustrative starting points**, not a statement that these Skills have already been built or approved.

### 1. Audit & Assurance

**Purpose:** Support structured audit and assurance workflows while retaining auditor responsibility for evidence, conclusions and reporting.

**Suggested subcategories**
- Statutory and company audit
- Internal and concurrent audit
- Bank and branch audit
- Tax audit (audit procedures and reporting)
- Audit planning, materiality and risk assessment
- Audit documentation and working papers
- Audit evidence, sampling and exception analysis
- CARO and other reporting requirements
- Standards on Auditing and quality management

**Example Skills:** `audit-planning-assistant`, `ledger-exception-reviewer`, `caro-checklist-generator`, `audit-working-paper-reviewer`.

### 2. Direct Tax

**Purpose:** Assist with direct-tax research, computations, filings, reconciliation and issue identification.

**Suggested subcategories**

## How to find the right Skill

1. **Browse by professional domain:** Select the category most closely related to the user's actual deliverable.
2. **Search by task:** Search terms such as "analyse financial statements", "reconcile GST ITC" or "draft engagement letter".
3. **Filter by tags:** Filter by subcategory, use case, intended user, output format, complexity or review status.

**Classification rule:** File each Skill in the category that owns its *primary professional outcome*. For example, `gstr-2b-reconciliation` belongs in **GST & Indirect Tax**, even if it uses Python or AI automation. Add tags such as `automation`, `excel` and `data-reconciliation` rather than creating duplicate copies in **AI, Data & Automation**. Use **AI, Data & Automation** as the primary category only when the Skill is genuinely cross-domain.

Suggested searchable fields are: `primary_category`, `subcategory`, `tags`, `intended_users`, `inputs`, `outputs`, `complexity`, `last_reviewed`, `review_status` and `owner`. These may be maintained in a separate catalogue/index; they need not all be placed in `SKILL.md` frontmatter.

## Skill documentation standard

Each Skill should be individually understandable, testable and maintainable. At minimum, document the following:

| Field | Requirement |
| --- | --- |
| Skill name | Clear, task-specific title and unique lowercase hyphenated identifier |
| Purpose | What the Skill does and when to use it |
| Intended users | For example, practising CA, CA in industry, audit staff or student |
| Expected inputs | Source files, data fields, assumptions and any mandatory user information |
| Expected outputs | Reports, schedules, checklists, analyses, drafts or structured data |
| Workflow | Steps, decision rules, review checks and error handling |
| Professional references | Relevant legal provisions, standards or authoritative sources, where applicable |
| Limitations | Unsupported cases, estimation assumptions and human-review points |
| Data-handling rules | Confidentiality, personal data, permitted systems and retention considerations |
| Test cases | Representative sample inputs and expected results |
| Ownership and review | Maintainer, version, review status and last-reviewed date |

For ChatGPT-compatible packaged Skills, use `SKILL.md` for the operational instructions. Its YAML frontmatter should contain the required `name` and `description` fields; additional catalogue attributes can live in a separate `catalog.yaml` file or central index.

## How to contribute a Skill

1. **Choose the primary category** based on the professional deliverable.
2. **Define the use case** in one sentence and identify a repeatable workflow rather than a general topic.
3. **Specify inputs, outputs and exclusions** before writing instructions.
4. **Create a uniquely named Skill folder** and its `SKILL.md`; add supporting references, scripts or templates only when necessary.
5. **Add searchable metadata and examples** so members can understand applicability without reading all implementation details.
6. **Test with representative cases**, including missing data, inconsistent data and ambiguous requests.
7. **Submit for domain and technical review** before changing the status to Reviewed.

**Naming examples:** Prefer `gst-itc-reconciliation` or `statutory-audit-planning` over names such as `gst-helper` or `audit-ai`.

## Quality, compliance and governance

Every published Skill should satisfy the following principles:

- **Professional accuracy:** Identify relevant law, standards and reporting periods. Do not treat AI-generated conclusions as automatically authoritative.
- **Human accountability:** Require appropriate professional verification of calculations, interpretations, judgments, representations and filings.
- **Traceability:** Clearly separate source facts, extracted data, assumptions and AI-generated inferences; provide references where feasible.
- **Confidentiality and privacy:** Do not expose client or member data to an unapproved service. Apply applicable confidentiality obligations, permissions and data-protection requirements.
- **Technical reliability:** Validate calculations, formulas, file conversions, edge cases and exception handling.
- **Transparency:** Disclose prerequisites, known limitations, relevant source dates and instances where expert review is mandatory.
- **Security:** Do not request passwords or secret keys in prompts; use approved credentials handling and least-privilege access for integrations.
- **Controlled publication:** Record a reviewer, last-reviewed date and revision history for each released Skill.

Recommended review states: **Draft → Under Review → Reviewed → Archived**. A Reviewed label should mean the Skill completed the repository's documented review procedure; it should not imply statutory assurance or institutional certification unless ICAI explicitly establishes and authorises that designation.

## Maintenance and versioning

- Use a consistent version scheme, such as `1.0.0`, and record meaningful changes.
- Reassess Skills when relevant laws, rules, notification requirements, standards, forms, APIs or supported tools change.
- Preserve a changelog for substantive updates, especially changes affecting outputs or professional interpretation.
- Periodically retest example cases and verify source references.
- Archive outdated or unsupported Skills instead of leaving them discoverable as current guidance.
